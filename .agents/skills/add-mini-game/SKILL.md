# 新增小游戏

把用户指定的小游戏接入当前网站，使其能从网站进入、正常游玩并重新开始，且不破坏已有游戏。保持需求范围；仅要求方案或原型时，交付相应内容，不自动扩展到发布、账号或后端系统。

## 确认玩法与当前结构

- 读取根目录 `AGENTS.md`，检查 `git status`、实际入口、构建脚本和已有游戏。存在 `docs/UI_STYLE.md` 或项目架构说明时读取相关部分。
- 从请求确认游戏名称/唯一标识、核心规则、操作方式及适用的胜负、计分、重开要求。能合理推断的细节先说明采用的方案；只有关键玩法无法确定时再询问，同时继续不依赖答案的仓库检查。
- 将需求整理成简短验收标准，并指出如何进入和离开游戏。按任务复杂度写入维护中的项目文档或任务交接，不为每个小任务制造空白模板。
- 当前初始仓库只有合成大西瓜单页：`index.html → src/main.ts → src/core/index.ts`。首次新增游戏或涉及接入架构时，读取 [接入与隔离约定](references/integration.md)，检查是否已经迁移；不能假设大厅、路由、注册表或生命周期接口已存在。

## 主 Agent 确定接入与分工

- 沿用项目已有的游戏入口和隔离方式。尚无多游戏结构时，完成支撑本次新增所必需的最小接入改造，保留原有合成大西瓜的入口与玩法，不把单纯增加一个游戏扩大成全站重写。
- 先确定游戏标识、入口/返回方式、资源位置，以及 UI 与玩法的事件和状态接口；采用模块挂载时明确挂载与退出清理责任，多页接入时明确构建入口和访问路径。
- 委派项目级 `frontend_layout` 负责入口、导航、UI 和响应式；委派 `gameplay` 负责规则、状态、输入和生命周期。主 Agent 负责接入集成及共享入口文件，先分配文件写入权；同一文件串行交接。
- 实现完成后委派 `qa` 按验收标准检查。仅在独立任务能并行时并行；不要把尚未确定的接口和共享文件交给多个子agent各自改写。
- 子agent 沿用父会话模型与权限，默认只返回修改和验证结果，由主 Agent 统一提交。若某角色不可用，说明实际情况，按其职责承接工作，不声称启动了未创建的子agent。

## 实现并接入网站

- 让新游戏拥有可用的入口、操作说明，以及适用于其规则的开始/重开和结束反馈。按约定更新入口列表或页面链接；不把只有独立源码、无法从网站进入的游戏记为接入完成。
- 将游戏状态、资源、样式和输入隔离在它自己的范围。退出/切换时清理计时器、动画帧、监听器和渲染实例，重新进入时得到预期的初始状态。资源与持久化键避免跨游戏冲突。
- 沿用既有技术和资源约定；普通新游戏不改 `src/b2/` 或 `public/*.min.js`。需要新增依赖时，先核对现有能力与实际必要性，不顺带升级无关依赖。
- 网站接入改变了目录或命令时，更新根目录 `AGENTS.md` 和相关运行说明，避免下一次新增仍按旧入口操作。

## 验证和交付

- 执行与改动相关的检查。当前生产构建为 `npm.cmd run build`，应用代码 lint 为 `npm.cmd exec -- eslint "src/**/*.ts" --ignore-pattern "src/b2/**"`，另检查 `git diff --check`；脚本变更后以实际配置为准。已有 CRLF lint 诊断应与新增问题分开记录。
- 当前没有自动化测试套件。对值得长期维护的纯逻辑，可按项目实际测试能力补充有意义的边界验证；不虚构测试命令，也不为复述实现而新增测试或框架。
- 有浏览器工具时实际验证：网站入口 → 新游戏 → 操作与规则 → 重开 → 返回 → 再次进入；回归原有合成大西瓜的加载、投放与合成，并检查桌面和手机布局。键盘/鼠标/触摸按本次支持范围验证，检查退出后有无遗留运行或输入响应。
- 将失败和复现步骤交回对应负责人，修复后做相关复测。缺少工具或环境时，明确未验证项目和影响，保留真实结果，不把构建成功写成玩法或视觉验收通过。
- 主 Agent 检查最终差异，只提交本次任务内容，按 `AGENTS.md` 使用中文 commit 并记录验证结果；无实际改动不创建空提交。`git push` 和发布按用户明确要求另行执行。
- 交付游戏入口、玩法与操作、修改文件、实际检查结果、未验证项及 commit ID。只有真实完成并验证的内容才标记为已完成。
