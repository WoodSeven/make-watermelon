# 游戏接入与隔离

当首次把单游戏扩展为多游戏，或新游戏需要改变入口/退出方式时读取本文件。先检查实际代码；这里描述的是初始仓库的限制和接入原则，不表示目标结构已经实现。

## 初始仓库的实际限制

- `index.html` 先加载 `public/box2d.min.js`、`public/pixi-6.4.2.min.js`，再加载 `src/main.ts`。`src/pixi.ts` 和 `src/box2d.ts` 使用对应的全局对象。
- `src/main.ts` 在导入时挂载 canvas、加载水果资源并设置窗口缩放；`src/core/index.ts` 维护模块级物理世界和水果状态，`init()` 注册输入并启动循环。它们不是无副作用的通用工具模块。
- 初始构建只配置了现有 HTML 入口，没有游戏大厅、客户端路由、注册表或可复用的销毁接口。不要先写一份虚假的注册记录就声称完成接入。
- 现有触摸处理依赖 `#root` 的 `marginLeft` 和 canvas 的 `transform`。仅改变容器位置或 CSS 缩放就可能影响投放位置，需要对照输入代码和实际操作验证。

## 按实际需要选择接入方式

优先遵循已建立的项目结构。首次接入时，可选择独立页面或同页模块，选择能满足本次需求且保留旧游戏的方案，并把决策和真实文件位置写入项目说明。

- 独立页面：保留游戏各自的初始化环境；正确设置 Vite 多页面构建入口、站内链接和静态资源路径。确认生产构建确实包含新页面，不能只验证开发服务器可以访问。
- 同页模块：站点外壳负责导航与当前游戏切换；各游戏按约定挂载到自己的容器，并提供退出清理。将必要的旧游戏启动逻辑封装后再复用，避免导入即运行全部游戏。
- 不论哪种方式，新游戏都要能通过网站入口到达。检查刷新、返回和重新进入，以及相对路径和部署 base 的关系；不能用个人电脑上的绝对路径作为入口。

## 与子agent 交接的最小内容

主 Agent 先约定游戏标识、入口/返回方式、UI 触发的操作、玩法提供的状态，以及事件和资源清理责任。只约定本次实际需要的接口，不为简单游戏预设复杂插件系统。

为主 Agent、`frontend_layout` 和 `gameplay` 划清文件写入权。若 UI 和玩法暂时在同一文件内，安排串行交接，不能要求两个子agent同时覆盖该文件。

## 生命周期与资源

- 游戏退出时移除监听器、清理 interval/timeout、取消 requestAnimationFrame、停止声音并释放实际创建的渲染或物理资源；再次进入时不能重复注册监听或多开循环。
- 不让一个游戏的 `window.onresize`、键盘监听、全局变量或 body/CSS 规则覆盖另一个游戏的行为。共享导航处理与游戏处理明确分工，输入只在适用的游戏和焦点范围生效。
- 将图片、音频等资源放在稳定、可区分的位置。需要保存成绩时使用包含游戏标识的存储键，重开当前游戏不清除其他游戏的数据。
- 手机适配同时核对视觉尺寸与点击/触摸坐标；页面提示、导航和按钮不能遮挡游戏操作区域。

## 接入验收证据

检查生产构建产物与资源加载、新游戏可达性、核心规则、重开、离开再进入、旧游戏回归，以及实际支持的输入与屏幕尺寸。分别记录构建/代码检查和浏览器验证的结果；尚未实现的得分、暂停或关卡等功能不自动扩展进本次验收范围。
